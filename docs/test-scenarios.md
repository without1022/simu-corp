### 2.4 Phase 1 端到端测试场景

**场景：CEO首次使用模拟公司 (SimuCorp)完成一个简单任务**

```
前置条件：所有服务正常运行，前端已打开

步骤1：CEO打开Dashboard
  - 看到四个统计卡片（在线Agent、进行中任务、待审批事项、本月花费）
  - 实时活动流显示系统启动以来的事件

步骤2：CEO在WebChat输入“帮我分析这个季度的销售数据有什么趋势”
  - EA回复：分析意图，确认需要数据分析能力
  - EA回复：当前无专职数据分析师，已委派GTF Manager

步骤3：EA发送 TASK_ASSIGN 给GTF
  - GTF确认收到任务
  - Dashboard实时活动流显示“GTF Manager 开始执行任务”

步骤4：GTF执行分析（模拟数据）
  - 10分钟后，GTF返回分析结果（销售趋势、关键发现、建议）
  - EA将结果转发给CEO
  - Dashboard活动流更新

步骤5：CEO查看结果
  - WebChat中显示完整分析报告
  - CEO回复“谢谢，不错”

步骤6：验证审计日志
  - 查询 /api/v1/system/audit-log
  - 应包含：message.sent（CEO→EA）、task.assigned（EA→GTF）、task.completed（GTF）、message.sent（EA→CEO）
```

## 5. 异常场景测试（全Phase通用）

| 编号 | 场景 | 模拟方式 | 预期行为 | 恢复验证 |
|------|------|---------|---------|---------|
| ERR-01 | Agent任务超时 | 给GTF分配一个它无法完成的无限循环任务 | EA在timeout后发送QUERY，无响应则重新分配给其他Agent | 任务最终完成或标记失败 |
| ERR-02 | Agent离线 | 手动停止GTF的Runtime进程 | EA检测到心跳丢失，GTF的任务自动转移给其他Agent | GTF恢复后重新加入能力目录 |
| ERR-03 | 模型降级 | 在模型中转站暂停主模型 | Agent自动切换到fallback模型 | 降级事件记录，任务继续执行 |
| ERR-04 | 分公司失联 | 停止分公司Gateway | 总部EA标记分公司离线，高时效任务转移 | 分公司恢复后自动重上线 |
| ERR-05 | 消息总线故障 | 停止Redis | Gateway启动本地内存队列，暂停跨Agent通信 | 恢复后回放消息 |
| ERR-06 | 全部模型失败 | 暂停所有模型提供商 | 关键任务暂停通知CEO，非关键任务标记失败 | 恢复后继续 |
| ERR-07 | 系统重启 | `docker-compose restart` | 优雅关闭→保存状态→启动恢复→Agent恢复工作 | 验证进行中任务恢复 |

## 7. 验收流程

1. 开发Agent完成模块后，先对照本文档进行自测
2. 将测试结果填入各测试项的“状态”列（⬜ → ✅ 或 ❌）
3. 对❌项附上失败原因和修复计划
4. Phase结束时，提交测试报告给CEO
5. CEO或测试Agent进行抽检验收
6. 所有关键测试项（标有“关键”的）必须全部通过
